# 交互、三维与约束类主题的补充规范

根目录 `AGENTS.md` 的数学正确性要求对所有主题适用；本文补充只有部分主题用到的细则：可拖动的交互、二维函数图、三维投影、向量与约束优化（如 `projects/kkt-conditions/`）。做这类主题时与 `AGENTS.md` 一起遵循。

## 二维坐标

- 数学坐标的 x/y 单位相同时，必须使用同一个屏幕比例尺，不允许按 SVG 宽高分别缩放 x/y（会把法向、切向和真实角度画错）。推荐：

```ts
const PLOT_SCALE = VIEW_H / (MAX - MIN);
const PLOT_W = (MAX - MIN) * PLOT_SCALE;
const PLOT_X = (VIEW_W - PLOT_W) / 2;
```

- 坐标转换、指针反变换、曲线、箭头、标签和命中测试共享同一套 `sx/sy`。

## 三维投影

- 明确区分数学空间中的向量和它在屏幕上的投影。
- 同一个 `project3d(x, y, z)` 用于曲面网格、坐标轴、等高截线、粒子、投影线和向量。
- 梯度画在定义域中时，应画在 `z=0` 平面而不是贴在函数曲面上；曲面点可用竖直投影线连接。
- 教学视角要说明优先目标。若要求等高截面不倾斜，圆的投影应为水平椭圆，左右极值点的屏幕 y 值必须相等。
- 2D 与 3D 同步视图中，同一点、同一函数值、同一等高线和同一向量必须同步更新。
- 简单教学曲面用确定性的 SVG 投影，不引入重量级 3D 库；确实需要旋转、遮挡和复杂曲面时再评估 WebGL。

## 向量与约束

- 若 `lambda = 1` 表示等比例作用，两个向量必须使用相同屏幕比例尺。
- 不等式约束的支持力仅在接触边界时出现；离开边界时对应乘子归零。
- 法向锥、可行域、切线、法线等从定义实时计算，不要写死在某个特殊点。
- 避免误导性符号：例如“可行域”和 `g(x)\le0` 之间使用正常排版间距，不加乘法点。

## 交互与状态

- 拖动使用 Pointer Events 并 `setPointerCapture`，拖出元素后仍连续更新。
- 指针屏幕坐标通过当前 SVG 的实际边界和同一坐标变换映射回数学空间。
- 对不可行拖动采用明确策略（投影回可行域、截断或拒绝），策略与教学文案一致。
- 公开可语义查询的 DOM 标记，如 `data-role="draggable-point"`、`data-role="objective-contours"`，便于测试。
- 状态面板只展示当前教学关系需要的数据（坐标、函数值、梯度、残差、乘子、条件是否成立），不为填满空间增加指标。

## 数值检查

交付时用数值验证关键几何关系，而不只凭截图：

- 垂直关系检查点积接近 0；
- 等比例向量检查屏幕长度；
- 2D/3D 同向检查屏幕 `dx/dy` 符号；
- 水平椭圆检查左右极值点 y 差为 0；
- KKT 检查残差、互补松弛和乘子非负性。

拖动至少检查边界点、内部点、交点和接近零的退化状态。
