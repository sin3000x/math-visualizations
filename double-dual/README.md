# 对偶的对偶

独立的第二集开场原型。水果袋、收银台及样式复制自 dual-space，在本项目内维护，不跨项目导入源码。

```sh
npm ci
npm run dev -- --port 4174
```

方向右键逐步展示：V 与 V* 及其中的水果袋、收银台同时出现 → 下方水果袋落在收银台托盘上，得到价格 16 → V** 中出现问号，下方托盘与价格也同步变成问号 → 上方与托盘的问号同步变成同一袋水果，价格同步恢复为 16。左键返回，数字键 1–4 跳转，PageDown / PageUp 同样可用。点击画布外“全屏录制”，Escape 退出。动画结束后等待按键，不自动推进。

画布内没有标题、说明和导航栏；普通模式在画布上方提供四个 Scene 的切换入口，点击进入该幕第一步并高亮当前项，录屏模式隐藏导航与工具栏；固定 16:9，按 1920×1080 验收。包含四个 Scene：第一幕从回顾到悬念，再揭示同一袋水果可以定义对收银台的测量；第二幕通过超市购物与物价调查对比固定收银台和固定水果袋；第三幕从两个坐标读数还原水果袋；第四幕呼应开幕，呈现原空间与双对偶的自然对应及有限维前提。

数学约定：沿用实数水果重量空间，袋子示例为 (2, 1)，收银台是权重 (5, 6) 的线性泛函，读数由点积计算为 16。图中仅展示各空间中的一个代表元素，椭圆表示集合，不表示有界性或距离。双对偶是对线性泛函再做线性测量的空间，最后用水果袋表示其对应的评价泛函：把任意收银台作用于这袋固定水果所得到的价格，作为对该收银台的测量。水果袋与评价泛函有自然对应，但属于不同空间；画面复用图标表达对应，并不宣称它们是同一个类型的对象。展示为正数的购买例子不限制空间中的坐标必须非负。

验证：`npm run lint`、`npm run build`、`npm test`。遵循根目录 AGENTS.md。

第四幕共 4 步：重现开幕的三个空间（双对偶中已揭晓水果袋）→ 收银台淡出，两侧空间与水果袋向中间靠近，出现双向对应箭头 → 标注“有限维”并显示 `V ≅ V**` → 提示无限维时自然映射仍存在，但不能覆盖整个双对偶。每步由方向键触发，移动历时约 1 秒，结束后停住；数字键 1–4 跳转。

第四幕的对应是 `v ↦ (f ↦ f(v))`，不需要选择内积。这里 `V = R²`，每个双对偶元素均唯一来自一袋实数重量水果：若双对偶元素在苹果、香蕉两个坐标读数泛函上的值为 `p, q`，则它在任意价格泛函 `(a,b)` 上的值为 `ap+bq`，恰好是水果袋 `(p,q)` 的结算结果。因此可把双对偶看成原空间；两种角色仍用不同颜色的空间轮廓区分。此同构结论使用有限维前提，不推广为任意无限维空间都成立。

新增超市场景共 6 步，第一幕结束后按右键进入，数字键 1–6 可跳转：

1. 购物者与一个固定收银台。
2. 一竖排三袋不同重量的水果。
3. 三袋水果依次进入同一个收银台，得到 11、16、17 元。
4. 调查员与固定的一袋水果（2 斤苹果、1 斤香蕉）。
5. 一竖排三个不同的收银台。
6. 同一袋水果的测量动画依次进入三个收银台，得到 16、13、19 元；源袋保持可见，移动图像表示同一袋水果的三次测量。

两组测量均一次按键触发。第一部分每袋动画历时 1.25 秒，完全消失后再等待 0.1 秒启动下一袋，起始间隔 1.35 秒，整组约 4.3 秒结束。第二部分起始间隔 0.4 秒，各袋到达后保留在对应托盘上，整组约 2.4 秒结束。到达后输出价格，结束后停住。可用左键回退并重新播放，不自动推进步骤。单价保留在代码中线性计算；画面不显示单价、店名或身份文字。角色使用统一日漫 Q 版 PNG，通过制服、红袖箍与记录板辨认调查员，价格仅用于教学。


第三幕“从读数还原水果袋”共 8 步：

1. 只显示未知线性评分规则 Φ。
2. 展示 f₁ 和价目表：苹果 1 元/斤，香蕉 0 元/斤。
3. 展示 f₂ 和价目表：苹果 0 元/斤，香蕉 1 元/斤。
4. 展示任意 f = af₁ + bf₂ 和价目表：苹果 a 元/斤，香蕉 b 元/斤。
5. f₁ 经过 Φ，得到数 2。
6. f₂ 经过 Φ，得到数 1。
7. f 经过 Φ，由线性得到 2a+b。
8. Φ 变成 2 斤苹果、1 斤香蕉的水果袋，所有输入与输出保持不变。

数字键 1–8 跳转，左右键跨幕。每次测量由按键触发，收银台图像移动进入 Φ 后输出数字，结束后停住。Φ 的输出没有预设货币单位；价目表的单位属于输入收银台的结算语境。最后水果袋表达数值相同的评价规则，不声称任意评分本来都是金额。示例读数 2、1 可换成任意实数 p、q；负数量表示退货或净流出。

讲稿：这两个收银台只是帮助我们找出袋子；真正的对应要求它对所有收银台都给出相同结果。自然映射定义为 J(v)(f)=f(v)，不需要选基。线性是从两个基础读数推及任意收银台的前提，讲解时明确说出。

讲稿中的有限维边界：有 n 个独立重量坐标时，n 个基础收银台的读数便足以唯一还原原对象，因为所有价格泛函都是这 n 个基础泛函的有限线性组合。无限维时，不能把这一步照搬为“读出无限多个坐标就结束了”：例如有限支撑序列空间的对偶包含任意系数序列，坐标读数泛函的有限线性组合不能穷尽整个对偶。代数双对偶中存在无法用原空间元素评价来表示的线性泛函。

本项目使用代数对偶（所有线性泛函），在通常的线性代数公理下，自然映射始终单射，且当且仅当原空间有限维时满射。参考 [Bourbaki, Algebra I, II §7.5](https://math.mit.edu/~hrm/palestine/bourbaki-algebra-1i.pdf)。若改用赋范空间的连续对偶，某些无限维空间仍可通过自然映射与连续双对偶同构（自反空间）；这是不同的讨论范围，不把“所有无限维连续双对偶都不能还原”作为结论。

基础收银台作用于水果袋时输出结算价格；Φ 作用于收银台时输出实数，画面不附加“元”。

## 自动录屏

录屏脚本由项目模板自带，读取 ScenePlayer 从注册表输出的 Scene 顺序与 `stepCount`，自动生成“展示 → 等待 → 按右方向键”的时间线，无鼠标点击或光标。新增 Scene / 步骤后无需重新编写脚本。适用于每按一次右方向键推进一步的 Scene；有内部键盘阶段或鼠标交互时需另行编排。

```sh
npm run video:debug              # 640×360，30 fps
npm run video:production         # 1920×1080，60 fps
npm run video:check              # 全步骤 1080p 抽帧检查，输出截图和 report.json
npm run video:debug -- --limit-seconds 5
npm run video:production -- <Scene稳定ID>
```

默认输出 `exports/<项目名>-<预设>.mp4`，可用 `--output exports/custom.mp4` 指定。`exports/` 不提交 Git。需本机 Chrome；可用 `VIDEO_BROWSER` 指定 Playwright 浏览器通道，`FFMPEG_PATH` 指定编码器。

在 `scripts/video/timeline.mjs` 修改 `timing`：普通步骤 3 秒，每幕末步 4 秒，时间包含动画及动画后的停留；`overrides` 按 Scene ID 配置各步骤的秒数，例如 `{ "my-scene": [3, 5, 4] }`。动画逐帧采集，渲染耗时不改变视频速度。`?export=1` 直接进入无工具栏录屏画面，`&scene=<ID>` 从指定 Scene 开始；Escape 可退出。

新项目仍使用仓库根目录的 `node scripts/create-project.mjs <项目名>` 创建，录屏脚本、命令和依赖随模板一同生成，各项目独立维护。
