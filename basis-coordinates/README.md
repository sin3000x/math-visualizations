# 基、坐标、行向量

独立第三集。目前实现五幕，沿用第一集水果袋的造型与实数净重量语义。

运行：`npm ci`、`npm run dev`。检查：`npm run lint`、`npm test`、`npm run build`、`npm run video:check`。

## 第一幕：两个袋子生成整个空间

1. 水果袋线性空间：包含正重量、分数、退货与零袋，袋子图案沿用第一集。
2. 选出 e1（1 斤苹果、0 斤香蕉）和 e2（0 斤苹果、1 斤香蕉）。
3. 直接展示任意袋子的线性组合，无动画，不显示 V 和椭圆。系数为任意实数 a、b：水果袋（a 斤苹果、b 斤香蕉）= a × 苹果单位袋 + b × 香蕉单位袋。负数水果用虚线轮廓，零斤项隐藏，袋子始终为实线。
4. 按右方向键，两个基袋移动到方括号内组成一行，系数 a、b 移到右侧组成一列，表示同一个线性组合。行向量以 V 中的基袋为条目，列向量是实数坐标，乘积仍是 V 中的袋子。动画完成后停住，左方向键可还原展开式。

方向键逐步推进，数字键 1–4 跳转当前幕的步骤。画布外提供场景切换与全屏录制，Escape 退出录制。固定 1440×810 设计、1920×1080 输出。画布无标题、说明与导航。

## 实现边界

播放器来自 scene-project 模板；FruitBag 与样式放在一起，图标复制自稳定项目。数学计算放在 lib/math/bags.ts，数字格式不固定四舍五入到一位小数。两集旧项目未迁移。后续独立教学目标以新增 Scene 扩展，不提前引入通用线性代数框架。

`npm run check:layout` 检查普通桌面、窄屏和 1080p 的全部步骤、对象边界与键盘导航，截图输出至 `exports/qa-layout/`。

## 第二幕：用基袋测出单价

依次展示收银台、一张静态线性性质图（上排加法 24 = 13 + 11，下排数乘 26 = 2 × 13）、屏幕上的两个问号单价、放入苹果单位袋、得到 5 元、苹果单价填入 5 并移除结果标签、换入香蕉单位袋、得到 3 元、香蕉单价填入 3 并移除结果标签。数字键 1–9 跳步；放袋动画结束后停住等待下一步。价格是重量的线性函数，不含起步费或折扣。

所有收银台从一开始均不显示小票。静态图与测价画面共用托盘和袋底坐标；单价位于放大的屏幕内。测价画面不显示基袋名称或函数公式。屏幕外文字统一浅白色，屏幕内文字使用深色，水果保持原有颜色。

## 第三幕：计算任意袋子的价格

紧接第二幕：屏幕保留苹果 5 元/斤、香蕉 3 元/斤；一袋 a 斤苹果、b 斤香蕉移动到同一托盘上。再按一次右方向键，显示 5a+3b 元。沿用测价画面的构图与配色。

第三幕继续按方向键：整体上移 → 袋子副本下移并变成坐标列向量 → 价格结果复制到下方 → 收银台副本下移并变成单价行向量。最终呈现 [5 3] 与 [a b] 的列向量相乘得到 5a+3b，上方原对象始终保留。

## 第四幕：换基，价格不变

顶部始终保留收银台、苹果 5 元/斤和香蕉 3 元/斤。沿用上一幕的称量托盘位置。原基袋用金色，新基袋用紫色，水果颜色保持不变。

1. 先展示原基袋 e1、e2。
2. 出现原袋和坐标系数，组成原袋 = 2e1 + 3e2。
3. 系数的数值副本从展开式移动成坐标列；屏幕中的单价数值副本随后移动成报价行，最后得到 19。
4. 下排先展示新基袋 v1、v2。
5. 下排从与上排对齐的等号开始，展示 = 2v1 + v2，不重复原袋。
6. v1 的副本移到顶部托盘，落稳后短暂显示 8 元，数值随即移入报价行第一格。
7. v2 的副本移到同一托盘，落稳后短暂显示 3 元，数值随即移入报价行第二格；托盘下没有基标签，收银台旁不保留报价。
8. 下排展开式中的系数数值副本移动成坐标列，再得到 19。两组坐标在展开式、动画与列向量中分别保持金色、紫色；行列乘积使用原生 KaTeX 矩阵和统一数学基线。

`tests/changeBasis.test.ts` 验证新基重建和配对结果不变，覆盖负数、分数和零。构建后运行 `node scripts/check-change-basis.mjs`，验证先基后坐标、等号对齐、异色基袋、托盘接触，以及矩阵数值的动画来源和中途位移。


## 第五幕：一般基下的结账行向量

延续第四幕，将具体的两袋基换成任意一组有序基 v1、v2。符号袋不指定苹果、香蕉的具体分量，不能理解为两个相同的水果配比。结账函数 f 仍然是线性的。

1. 展示两个符号基袋与线性结账台。
2. 展示 v = a v1 + b v2，坐标沿用基袋的紫色。
3. 用线性性得到 f(v) = a f(v1) + b f(v2)。
4. v1 上托盘，结账结果 f(v1) 短暂停留后移入行向量第一格。
5. v2 上托盘，结账结果 f(v2) 短暂停留后移入第二格。
6. a、b 从袋子展开式移入坐标列，最终在同一行展示 f(v) = a f(v1) + b f(v2) = [f(v1) f(v2)] [a b] 的列向量乘积；收银台、袋子展开式与连等式居中排列。

这一行依赖所选基及其顺序；行中的每一项是整个基袋的报价，不一定是某一种水果的每斤单价。此处的元是同一计价单位；线性空间允许实数坐标，包括负数。

构建后运行 `node scripts/check-general-basis.mjs`，检查不同基与线性报价的数值恒等式、六步显隐顺序、基袋接触托盘、报价逐项入行及坐标入列的实际动画起点。


## 导出录制视频

在本子工程目录运行（需已安装 Google Chrome）：

```bash
npm run video:production
```

输出 `exports/basis-coordinates-production.mp4`，1920×1080、60fps、H.264，无音轨。自动播放注册表中的五幕共 33 步，不显示鼠标或导航。逐帧推进浏览器动画时钟，机器渲染慢不会造成丢帧或加速。

每一步先完整播放 CSS / Web Animations 动画（包含延迟），再停留 3 秒；每幕最后一步停留 4 秒，然后按右方向键继续。无限循环装饰动画不阻止推进。当前场景使用的动画均由此时钟覆盖。

```bash
# 调整动画结束后的停留时间；适合后期配音
npm run video:production -- --hold-seconds 5 --scene-end-seconds 7
# 单独导出最后一幕
npm run video:production -- general-basis-checkout-row
# 快速导出全部内容：640×360、30fps
npm run video:debug
# 1080p 检查所有步骤、动画结束状态并保存抽样截图
npm run video:check
```

`--output exports/custom.mp4` 可指定文件名。视频旁的 `.mp4.json` 记录各步开始时间、动画时长、停留开始时间与结束时间，便于对照配音。`--limit-seconds` 仅用于截取调试，会截断动画或停留；完整导出不要使用。编码成功后才生成最终文件名，`.partial.mp4` 是未完成的临时文件。视频与验收产物均不提交到 Git。
