# 线性映射与矩阵

在根目录运行 `npm run dev -w linear-map`。方向键逐步推进，数字键跳步；外部工具栏进入全屏录制，Escape 退出。画布固定 16:9，底部 16% 留给字幕。

## 数学模型与口播约定

水果袋空间 V 沿用苹果、香蕉两种分量，单位为斤。输入有序基 E=(e₁,e₂) 是一斤苹果、一斤香蕉。
果汁空间 W 有A 果汁、B 果汁、C 果汁三个分量。每个读数单位为 100 mL；输出有序基 U=(u₁,u₂,u₃) 是这三类果汁各一个产量单位。三种杯子从左到右始终为 A、B、C，依次对应矩阵的第一、第二、第三行，颜色始终为青、蓝、紫；矩阵中的数字沿用所在行的果汁颜色，列顶用苹果、香蕉图标区分两列。

这是固定工艺、固定产量的理想模型；A、B、C 表示三种固定输出类别，忽略口味组成、损耗变化、批次和容量限制，不是真实榨汁配方。每斤苹果的三项产量为 (2,1,1)，每斤香蕉为 (1,2,1)。

口播先交代：袋子和杯子表示可加减的净数量；正数是增加，负数是扣除，零是没有净变化。实际存量非负，只是实向量空间的一部分。线性关系对任意实系数成立；画面用非负例子建立直觉。

## 分镜

画面只用对象和动作讲关系：一托盘三杯果汁是 W 的一个元素；托盘相加就是把一托盘倒进另一托盘，数乘就是同一托盘的液面按倍数连续伸缩（小数倍同样自然）。结果总是作为新的托盘从榨汁机出来。读数在倒入或伸缩结束后才更新。

各幕首尾相接：每一幕的第 1 步复现上一幕的最后画面，第 2 步把保留下来的对象连续移到本幕布局，其余淡出。共享坐标在 `scenes/layout.ts`。

1. JuiceSpaceScene：一托盘 (1,2,1)；再来一托盘 (2,1,0)；倒在一起得到 (3,3,1)；出现 ×2；液面升到 (6,6,2)；它缩进右侧的 W，W 中还有许多托盘。W 中其他托盘只表示空间元素，与榨汁机无关。
2. JuiceMapScene：复现 W；示例托盘淡出，V、三袋与榨汁机 T 出现。T 在两集合上方，表示对应规则；每一步一袋，袋子与同一行的托盘用一条箭头直接连起来，T 同时运转一次：(2,1)→(5,4,3)、(1,3)→(5,7,4)、(3,0)→(6,3,3)。
3. MachinesScene：复现上一幕；(2,1) 与 T 留下并移位，S、R 出现；三台同时得到 (5,4,3)、(3,5,2)、(4,2,6)。S 的两列为 (1,2,0)、(1,1,2)，R 为 (2,0,2)、(0,2,2)。后续各幕固定使用 T。
4. LinearityScene：复现上一幕；(2,1) 与 T 移到右列；写出 (1,1) + (1,0) = (2,1)；三列同时榨汁；托盘写出 (3,3,2) + (2,1,1) = (5,4,3)。再写出 0.5 × (2,1) = (1,0.5)；两列同时榨汁；托盘写出 0.5 × (5,4,3) = (2.5,2,1.5)。
5. BasisImagesScene：复现上一幕；(1,0.5) 移到右上，T 移到苹果行；苹果、香蕉基袋同时榨汁，得到 (2,1,1)、(1,2,1)；(1,0.5) 拆成 1 袋苹果、0.5 袋香蕉；抄来两只托盘，香蕉托盘液面 ×0.5 变为 (0.5,1,0.5)，再倒进苹果托盘，得到 (2.5,2,1.5)，不再需要榨汁机。
6. MatrixScene：复现上一幕；两只基袋与托盘移到上方，两部分合回 (1,0.5)；托盘读数按列移进方括号，列顶为水果、行首为果汁杯；袋中的 1 与 0.5 飞到列顶作为权重；右边出现 (2.5,2,1.5) 和对应托盘。矩阵依赖苹果、香蕉与 A、B、C 的固定顺序。

W 是三维空间，但这个映射的输出只落在其中一个二维子空间：第三项等于前两项之和的三分之一。无需把“输出空间三维”误说成“任何三杯都可由水果袋产生”。本期画面不额外展开秩与像空间。
